# Parlance: notes for Claude Code

Parlance is Matt's own German, Latin American Spanish and Italian course, a replacement for Babbel and Duolingo. He uses it mostly on his Android phone, in Chrome: the web version installed to his Home Screen, and the Claude version. Check audio, speech and layout changes in Chrome on Android first (about 412px wide). Some of his friends use iPhones, so Safari still matters. It is a static web app with no build step: the files in this repo are the files that run. It is published as a multi-file Claude artifact:

**https://claude.ai/artifact/8ZNHqMUCms2THTSfDkTp72**

There is also a **web version** for people without Claude at **https://parlance-iota.vercel.app**. Vercel (project `parlance`) builds it from `main` with `node dev/web.js` (see `vercel.json`). Its accounts and database are the Supabase project **Parlance** (`ibrweunxigetiazzuwiz`). The tutor features (Talk, lessons on demand, tutor grading, Studio synthesis) stay Claude-only. See "Two homes" in `docs/ARCHITECTURE.md`.

The look is **Selva** (built in 4.4.0). The remaining design choices (Pip and the cast style) are in Claude Design: https://claude.ai/artifact/Qzi2d6c6LteToAfVtkPqJd, with notes and concept-art sources in `design/`. The character rig is in `design/rig/`: all five birds (Pip, and Kiwi, Mango, Kakadu and Rojo, which learners can pick instead in Me → Your bird) are traced from their model sheets and rigged in Blender (`design/rig/blender/<bird>.blend`, played by `pip3d.js`). Read `design/rig/README.md` and `design/rig/blender/README.md` before touching a bird's art or moves, and run `node design/rig/check.js`.

Read `docs/ARCHITECTURE.md` before changing anything. It maps every file and explains live content, the feedback loop and the theme song.

## Ground rules

- **Progress must never be lost.**
  - Never rename or reuse a lesson or story id.
  - Keep the storage key `parlance.v2` and the database paths.
  - When the saved shape changes, bump `SCHEMA_VERSION` and add an idempotent step to `MIGRATIONS` in `js/core/state.js`.
  - Merges must keep fields they don't recognize.
- **Change things once, in their home.**
  - Colors, type, spacing, radii, motion and layers live in `styles/tokens.css`. Don't write literal colors elsewhere.
  - Version, release notes, XP, quests, badges, Talk scenarios, the birds learners can pick and media live in `js/config.js`.
  - Sounds are entries in `SOUNDS` in `js/core/audio.js`; play them with `sfx('name')`.
  - Music goes through `Song` and `MEDIA.song`.
  - Speech goes through `speak()`. Recorded voices are `MEDIA.voice` and `media/voice/`, made by `dev/voices.js`; see "Recorded voices" in `docs/ARCHITECTURE.md`.
  - Icons live in `IC` in `js/core/util.js`.
  - The birds are drawn by the rig: `js/core/rig.js` (runtime), `js/core/bird.js` (the shared bird: skeleton, poses, moods, moves) and a part sheet per bird: `js/core/pip.js` (written by `design/rig/tools/trace/build_pip.py`) and `kiwi.js`, `mango.js`, `kakadu.js`, `rojo.js` (written by `design/rig/tools/trace/run.sh <bird>`; loaded only when picked). `js/core/art.js` wraps them as `pip()` (the learner's bird, alive) and `pipSVG()` (a still). Their colors are the `--pip-*`, `--kiwi-*` … tokens. The birds learners can pick are `MASCOTS` in `js/config.js`; the choice is `settings.mascot`.
  - Word pictures are `PICS` in `js/core/pics.js` (the Sticker style, colored only through the `--pic-*` tokens); which word gets which is `PIC_WORDS` in `content/pictures.js`, generated by `node design/pictures/tools.js words` from `design/pictures/briefs-src.txt`. See "Word pictures" in `docs/ARCHITECTURE.md`.
  - The cast and the other illustrations are pure SVG functions in `js/core/art.js`. The cast figures and story scenes drawn in Recraft are SVG files in `media/cast/` and `media/scenes/`, placed by `design/pictures/tools.js svg`.
- **Content is data** in `content/*.js`.
  - A lesson needs 4+ vocab, 3+ sentences, and blanks with exactly one `___` and 2+ distinct options.
  - Spanish is Latin American: *ustedes*, never *vosotros*.
  - Italian is standard Italian: *tu* with friends and *Lei* when formal. Write elisions with the typographic apostrophe (*l’acqua*, *un’amica*) and keep the sentence-ending period outside a bold example in a tip body (`**Mi chiamo Matt**.`), or the tip can't be cut into bites there.
  - Every language has the same shape: 33 units and 132 lessons (A1 to C2) and 9 stories. A new language starts with `LANG_IDS` in `js/config.js`; see "Adding a language" in `docs/ARCHITECTURE.md`.
- **Copy** is plain, warm English in sentence case.
- **Scripts** are classic (not modules) and load in the order `index.html` lists them. A later file can use anything an earlier one defined. An event handler that can fire before the UI scripts have loaded must guard with `typeof`.
- **Check the design** in `styleguide.html`, a living style guide rendered from the tokens and art functions.
- **Accounts and the database go through `window.claude.use()`** and nothing else. In the artifact, Claude provides it; on the web, `js/core/host.js` provides the same surface from Supabase. Keep the two in step: a new database path or rule goes in both the artifact's rules and `dev/supabase.sql`.

## Commands

```sh
npm ci && npm test   # jsdom end-to-end suite (~2 min). Must end with "FAIL 0".
npm run preview      # http://127.0.0.1:8765/_preview.html
node design/pictures/tools.js check   # word pictures: drawing rules, the word mapping, coverage (must end with ok)
npm run files        # JSON map of the files to publish next to index.html
npm run web          # builds the web version into dist/ (what Vercel serves)
NODE_PATH="$(npm root -g)" node dev/icons.js   # redraws media/icons/ from Pip (needs Playwright)
node dev/voices.js   # records new lines into media/voice/ (Google key: the environment's network secret; --dry counts them)
```

A GitHub Action (`keep-awake.yml`) reads the web database three times a day so the free Supabase project doesn't pause. If it fails, the web version's database is down.

The preview runs without the artifact runtime, so there is no account sync, database or tutor; the app handles their absence.

## Shipping a release

1. Bump `APP_VERSION` and add a `RELEASES` entry in `js/config.js`. People who were already learning see What's new once.
2. If lesson or story text changed, run `node dev/voices.js` so the new lines are recorded, and commit `media/voice/` with `dev/voice-usage.json`. Recording must never cost Matt anything: the script stops at 900,000 characters a month, under Google's free million. Never raise that cap or get around it. If the script stops or Google turns the key down, say so: those lines use the device's voice until they are recorded.
3. Run `npm test`. It must end with `FAIL 0`.
4. Commit to `main` and push. Vercel deploys the web version from `main` on its own.
5. Publish with the Artifact tool:
   - `file_path`: the absolute path to `index.html`
   - `url`: the artifact URL above
   - `files`: the map from `node dev/files.js "$PWD"`, which gives absolute sources. Sending only the changed files is fine.
   - Leave `capabilities` out so the declared ones carry forward.
   - If the publish is refused because the published files differ from what this session has seen, read them first (Artifact `read` with `paths`), check the differences, then publish.
   - Only served file types publish. For media that means `.mp4`, `.webm`, `.mp3`, `.ogg` or `.wav`, not `.m4a`.
6. Set `content/config` → `latest` to the new version in **both** homes. Anyone with Parlance open then gets a Refresh banner. Matt can also do this from Me → Studio → Content in each version.
   - Artifact: ArtifactData. Read the doc first and pin `if_version`.
   - Web: Supabase `execute_sql` on project `ibrweunxigetiazzuwiz`:
     `insert into public.docs (path, coll, data) values ('content/config', 'content', '{"kind":"config","latest":"X.Y.Z"}') on conflict (path) do update set data = public.docs.data || excluded.data, updated_at = now();`
   - Live content packs are per home too: write a pack to both if both should have it.

## Feedback → proposals → approval → build

- Learner notes are in the database at `feedback/<uid>` as `{ items: [{ id, at, type, text, ctx }] }`. Only the owner can read them. Web learners' notes are in the Supabase `docs` table at the same paths (`select path, data from public.docs where coll = 'feedback'`); Studio synthesis needs Claude, so turn those into proposals from the artifact or a Claude session.
- Proposals are at `proposals/<id>`:
  - Fields: `title`, `kind` (content|code|design|copy), `summary`, `problem`, `change`, `evidence` (feedback ids), `impact`, `effort`, `status`, `createdAt`, and optionally `note` (Matt's note for the builder).
  - `status` is `pending`, `approved`, `rejected` or `shipped`.
  - `proposals/_meta.lastSynthAt` marks the newest feedback already turned into proposals.
  - See `synthesize()` in `js/ui/studio.js`.
- Feedback is collected on the **web version only** (Claude copies send people there). `node dev/feedback.js open` prints SQL for the open notes and approved proposals; run it with Supabase `execute_sql` on project `ibrweunxigetiazzuwiz`.
- **Only build proposals with `status: "approved"`.** Matt approves them in the app (Me → Studio). Follow his `note`.
- After shipping, close the loop for each built proposal: `node dev/feedback.js close <version> "<one warm sentence on what changed>" --proposal <id>`, then run the SQL it prints. That sets the proposal to `shipped` with `version` and `shippedAt`, and marks the learners' notes resolved, so each of them gets a thank-you with your sentence the next time they open Parlance. Write the sentence for the learner, in plain, warm English. Studio → Proposals → Mark shipped does the same.
  - Notes with no proposal: `... close <version> "<message>" --notes <id,id>`.
  - If the proposal lives in the Claude artifact's database, use ArtifactData to set the `shipped` fields instead, and Studio there for the notes.

## Database rules (declared at publish; keep them)

```
content          read: view    write: owner
proposals        read: owner   write: owner
feedback         read: owner   write: owner
feedback/{self}  read: interact  write: interact
cards            read: interact  write: owner
cards/{self}     write: interact
inbox            read: interact  write: interact
data/users/{self}  private to each person (platform default)
```

`cards` and `inbox` are for Friends (see "Friends" in `docs/ARCHITECTURE.md`). Their paths include each person's secret, so only people they invite can find them.

Capabilities: `db`, `user` (profile scope), `sample`, `downloads`, `comments` (composer only). Changing a rule means passing the whole `capabilities` object on that publish (every capability and every rule above); leave it out on other publishes.

The web version enforces the same rules in SQL (`dev/supabase.sql`). Owners there are listed in `public.owners`.
